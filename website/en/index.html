One chain, from user reasoning to businessSCENE → BUSINESS

Data collection, interviews, experiments, and platform connectors are supporting steps only — they validate a node or an inference edge; they never replace the reasoning itself.

Scene→ User→ Pain→ Need→ Feature→ Product→ Business

Every node must record: the current statement, the rationale, the assumptions it rests on, the supporting evidence (evidence_ids), and a status. One machine truth (product-reasoning.json) projects into the MRD, PRD, BRD, and decision memo — not four parallel sources of fact. Six kinds of conclusions are never mixed: need does not pose as acceptance, usability does not pose as commercial, and stated intent is never paying behavior.

How need validation worksNEED VALIDATION

A user saying "I want it" is only E1, a verbal statement. To reach "validated", a judgment needs at least one piece of E2 — an observed substitute, workaround, or failure behavior. The full method is in "When a user says 'I want it', is it a need?": four common misreadings, a substitute-behavior checklist, and the E0–E5 criteria — usable without installing any tool.

The two judgments with only E1 do not get upgraded because "many people say so"; a cell with no evidence says "unknown", never "zero". That is what askovo audit does: a judgment marked "validated" whose question chain holds only E1 is named and recommended for downgrade, and exit code 1 can gate CI (regression tests in tests/test_askovo_cli.py). Run askovo demo locally to see one full audit output.
