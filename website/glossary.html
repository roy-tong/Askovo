七节点推理链THE SEVEN-NODE CHAIN

从用户推理到产品与商业的主链，也是全部交付物的骨架：

场景→ 用户→ 痛点→ 需求→ 特性→ 产品→ 商业

scene → user → pain → need → feature → product → business。每个节点必须填写：当前判断（statement）、推导理由（rationale）、成立假设（assumptions）、支撑证据（evidence_ids）与状态。MRD、PRD、BRD 与决策包都是这条链的投影。

E0–E5 证据分级EVIDENCE LEVELS

引擎内部的证据分级，用于门禁与审计，不上业务交付物正文（正文用业务语言，分级只在文末方法档案）。逐级定义：

级证据形态回答的问题
E0活动、角色或场景背景场景出现
E1未满足任务、目标或困难问题被表达
E2当前做法、绕行、失败或切换成本替代方案及摩擦
E3对研究方案的明确接受/偏好方案在给定条件下被接受
E4+价格锚点、购买/付费表达直接商业意图
E4−拒绝、取消、退货、放弃直接负面商业行为
E5付费持有、部署、持续使用、复购已实现的行为证据

两条硬规则：需求节点升到 validated 至少要一条 E2（观察到的行为）——仅有 E1 口头陈述只能停在 needs-validation，说了不算，做了才算；商业节点只认 E4+/E5，反证与替代行为不会把它抬成「已观察到」。

E0–E5 只描述需求与商业证据强度，不是产品/商业推理得分；可用性、工程性能、安全、可行性各有自己的验证要求。

●◐○ 依据强度标记READING AIDS

业务方案正文里的阅读辅助，按节点取级：● 已观察到 · ◐ 有线索 · ○ 假设。场景/用户/痛点/需求接受 E2 及以上的行为记录；特性/产品只认 E3（方案接受）及以上；商业节点只认 E4+/E5。

SURE 证据引擎SURE ENGINE

SURE = Structured User Research with Evidence。Askovo 是产品（CLI / Agent Skill / MCP / 包），SURE 是其下的研究与证据引擎：管方法选择、证据形式与分级、主张边界、反幸存者偏差、安全门与判断约束。一句话：Askovo 负责「从用户推理到产品与商业」，SURE 保证「每一步都知道证据实际够到哪」。

六类结论SIX CONCLUSION TYPES

need / acceptance / usability / performance / commercial / safety 六类结论不混：need 不冒充 acceptance，口头意愿（E1）永远不是付费行为（E4+/E5）。逐类边界见 claims 页。

超证OVERCLAIM

结论超出了证据能支持的范围——比如把 E1 口头意愿写成「用户愿意付费」。askovo audit 逐条检查超证并点名，发现时退出码 1，可以进 CI 当门禁。

主链真值MACHINE TRUTH

product-reasoning.json 是七节点链的唯一语义正本；MRD、PRD、BRD、决策包都是从它投影出来的读者视图，不是平行事实源。改判断只改真值，投影随之更新。
