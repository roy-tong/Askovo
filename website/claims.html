CLAIMS & BOUNDARIES

我们主张什么，不主张什么

Askovo 的价值在于知道证据能支持到哪里。这一页把产品自己的主张也放进同一条纪律里：能主张的写清楚，不能冒充的直接说不。

六类结论不能混SIX CONCLUSION TYPES

类型回答不能替代
need谁在什么场景有什么未满足任务功能请求、个案、普遍率
acceptance用户是否理解/接受方案喜欢 ≠ 会用 / 会买
usability能否完成任务、是否易学低错好用 ≠ 需求成立
performance明确条件下是否达标跑分 ≠ 体验
commercial购买、留存、复购、退换口头意愿 ≠ 交易
safety使用风险与合规缺口用户试验 ≠ 认证

E0–E5 只描述需求与商业证据强度，不是产品/商业推理得分；可用性、工程性能、安全、可行性分别有各自的验证要求。

测试与样例证明什么WHAT TESTS PROVE

证据能主张不能冒充
135 个单元测试（Python 3.9–3.12）命令行为、结构校验、门逻辑符合规格真实需求成立、产品质量、市场规模
离线合成样例（askovo demo）主链、证据引用与审计逻辑自洽任何真实用户或商业事实
CI 通过（tests.yml）上述行为在受支持版本上可复现发布可行性、合规或认证
GitHub/Reddit 官方 API 采集授权来源的原始记录与偏差留痕样本代表总体、记录数=用户数

永远不做的推断NEVER

  • 不把购买意愿当真实购买，不把采用率当产品结果，不把一次喜欢当复购
  • 不把便利样本外推普遍率或市场规模；市场估计必须写全口径、边界与来源，null 是未知不是零
  • 不把 decided（记录了当前选择）冒充发布批准、商业成立或因果效果——交付、结果、因果是三个独立状态
  • 不做未授权抓取，不绕过 blocked 连接器、登录墙或平台挑战
  • 所有自动交付默认草稿；CLI 通过不替代人工语义复核、产品签收或风险接受
