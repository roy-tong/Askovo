# 市场、需求与商业分析

askovo 的主链是：

> **场景 → 用户 → 痛点 → 需求 → 特性 → 产品 → 商业**

不同岗位的交付物不同，但都必须完善同一条推理链。这里的“分析”不是某个岗位的专属文档工作，而是把研究证据转化为可验收、可追溯、可决策的产品与商业判断。

## 1. 三条工作流，三份正式产出

| 工作流 | 过程 | 正式产出 | 回答的问题 |
|---|---|---|---|
| 市场研究与市场分析 | 市场边界、细分、竞品与替代、渠道、价格、交易和规模的证据采集与分析 | **MRD** | 哪个市场、为谁、以什么价格和渠道进入更有依据？ |
| 需求研究与需求分析 | 用户/市场需求、利益相关方需要、业务与技术约束的研究、优先级、验收与追溯 | **PRD** | 因此应承诺什么特性、产品范围、非目标和验收？ |
| 商业分析 | 收入模式、成本、单位经济、资源、风险与业务门的比较和决策 | **BRD** | 这个产品如何形成可验证的商业闭环，是否值得继续投入？ |

它们不是三套事实源：

- 三份文档都读取 `04-findings/product-reasoning.json`；
- 市场分析主要充实商业节点的市场部分；
- 需求分析主要维护 need → feature → product → business 的追溯、验收和变更；
- 商业分析主要充实商业节点并形成 BRD。

BRD 不与其他工作流并列。**BRD 是商业分析的产出。**

## 2. 五类“需求/研究”不要混

| 工作 | 核心问题 | 不能证明 |
|---|---|---|
| 市场研究 | 市场、竞品、渠道、交易、客户和组织的事实是什么？ | 未定义边界的市场总量；商业成立 |
| 市场分析 | 如何界定和比较细分、替代、价格、规模与进入顺序？ | 用户需求本身；精确份额或因果 |
| 用户需求研究 | 特定 scene × user × task 中，人要完成什么？ | 市场会买什么、买多少；总体流行率 |
| 市场需求研究 | 在明确边界、价格、渠道和时间下，谁愿意且有能力付费、付费多少、是否持续？ | 口头意愿等于交易；TAM 等于本链需求 |
| 产品/业务需求分析 | 如何把需要变成可验收、可追溯、可治理的要求？ | 商业目标可以倒写用户痛点；PRD 完整等于产品成立 |

一句话：

- **用户需求研究**回答“人要完成什么”；
- **市场需求研究**回答“市场会买什么、买多少、以什么条件买”；
- **需求分析**回答“因此应承诺和交付什么，如何验收与治理”。

## 3. 职责覆盖

| 角色 | 应负责 | 不天然拥有 |
|---|---|---|
| 产品经理 | 全链决策、优先级、范围/非目标、验收、商业门与剩余风险；组织三类分析 | 抽样/统计/伦理独立性；不能独自证明市场、财务、技术或因果成立 |
| 用户研究 | 研究设计、抽样、采集分析、证据质量、反证与替代解释；支撑 scene/user/pain/need 和方案接受/可用性 | 最终定价、渠道、资源分配和商业门；便利样本不能代表总体 |
| 用户运营 | 行为分群、采纳/留存/召回、渠道干预、异议处理和有分母的行为指标；把反馈回流到主链 | 可触达用户不是全市场；使用/好评不能单独证明需求、商业价值或因果 |
| 市场研究 | 市场数据来源、竞品/替代、渠道、客户和交易事实；披露方法与限制 | 证据本身不等于市场选择；不能把竞品报价当自己的价格证据 |
| 市场分析 | 市场边界、细分、规模口径、价格/渠道/进入假设及 MRD 候选基线 | 用户需求；商业批准；精确规模或份额 |
| 需求分析 | need/requirement 的转换、优先级、验收、追溯、变更和 PRD | 市场需求和商业成功；不能用功能请求代替需求 |
| 商业分析 | 商业模型、单位经济、资源门、风险与 BRD | 产品已成功；用户/交付证据可以由财务假设替代 |

小团队可以让 PM 兼任市场、需求或商业分析，但**工作流不能因此消失**。当结论涉及市场规模、财务、法规、技术可行性、安全或高风险人群时，需要相应专业复核。

## 4. MRD、PRD、BRD 的关系

| 文档 | 主要输入 | 主要输出 | 在七节点中的位置 |
|---|---|---|---|
| MRD | 市场研究/分析、用户需求证据、战略边界 | 市场边界、细分、竞品/替代、渠道、价格、规模口径、进入顺序和缺口 | 商业节点的候选市场视图，并回读前三节点 |
| PRD | 已识别的 need、候选方案、市场与商业约束、可行性输入 | 特性、产品范围、非目标、优先级、验收、追溯和变更 | need/feature/product 的正式投影 |
| BRD | MRD 候选选择、产品价值、支付/交易、成本、渠道、资源和风险 | 商业选择、目标与成功指标、收入/成本、单位经济、业务门和停止条件 | business 节点的正式决策投影 |

基线顺序可以是：

```text
探索研究 → MRD 候选市场基线 → BRD 商业决策基线 → PRD 产品承诺基线
→ 交付与结果观察 → 回写主链
```

这不是强制瀑布。BRD 可以先提供预算或资源边界；MRD/PRD 的新证据也能触发 BRD 变更。所有文档必须引用同一 `chain_id` 和版本，不能各存一套市场、价格、需求或产品事实。

## 5. 商业节点与 BRD 的字段

`business` 节点至少记录：

- 市场定义、地理范围、时间窗、纳入/排除市场；
- 目标细分、细分标准、付费者；
- 竞争定位与替代方案；
- 渠道、收入模式、价格假设和价格证据；
- 成本驱动、单位经济输入；
- 市场估计：指标、总体、时间窗、单位、公式、来源与不确定性；
- 商业成功指标与护栏；
- 商业非目标、业务门、负责人、资源承诺和复审触发；
- 优先级方法、因素、决策日期和理由；
- 变更记录和投影同步状态。

BRD 只投影这些内容，不另建数字。未知保留为未知，不能用 0、假精确值或市场规模填满。

## 6. 证据与推断纪律

1. **市场研究和市场分析都包含分析**：研究不是只采集，分析也不是没有来源的计算。
2. **事实、解释、建议分层**：先写直接观察到的事实，再写研究解释，最后写决策建议。
3. **抽样披露**：说明总体、抽样框、选择方式、招募、样本量、加权、局限和推断范围。
4. **便利样本不能推总体**：评论、帖子、工单、访谈条数是记录，不是用户数、需求率、销量或市场份额。
5. **市场规模的每个数字都要有口径**：边界、指标、总体、时间、单位/币种、公式、输入和来源；不能把 TAM 当作本链需求。
6. **支付证据分层**：挂牌价、口头支付意愿、预订、真实购买和续约不能互换；付费者和使用者可以不同。
7. **单位经济可复算**：先定义核算单位；贡献毛利 = 净收入 − 可变成本；CAC/LTV/留存必须有 cohort、时间窗和模型或成本范围。
8. **优先级不是词频**：必须有方法、因素、证据、决策人和日期；便利样本的 reach 不能变成高优先级。
9. **追溯不是只查 ID**：特性回链需求，产品回链特性，商业回链产品；每条边要有 rationale，证据不能代替推理。
10. **变更先改真值**：先更新主链和影响项，再同步 MRD/PRD/BRD；投影标 `pending` 时不能假装已同步。
11. **业务门与安全门分离**：商业通过不能抵消安全/伦理 HOLD，也不能证明因果。

## 7. CLI 使用

```bash
askovo chain ./study
askovo deliver ./study --kind mrd
askovo deliver ./study --kind prd
askovo deliver ./study --kind brd
askovo check ./study --stage full
```

`mrd.md`、`prd.md`、`brd.md` 都从同一主链渲染。`chain decided` 只记录当前产品/商业选择；`delivery`、`outcome`、`causal` 仍是独立状态。
