# Askovo 文档

askovo 用同一主链服务五域产品经理、用户研究、用户运营及市场/需求/商业分析职责：**场景 → 用户 → 痛点 → 需求 → 特性 → 产品 → 商业**。Skill 负责判断，CLI 负责确定性操作，MCP 只包装同一命令行为。

第一次来，按这个顺序读：

1. [快速开始](quickstart.md) —— 从 `do/chain` 到补证、审计和角色交付。
2. [产品与商业推理主链](product-reasoning.md) —— 七节点、推导边、商业门、反证与人工复核。
3. [市场、需求与商业分析](business-analysis.md) —— 三条分析工作流及 MRD/PRD/BRD 的关系。
4. [岗位方法论](product-methodology.md) —— 五域 PM、资深 UXR、用户运营与分析职责的方法来源。
5. [五类产品](modes.md) —— 同一主链下的配置、验证和专业门差异。
6. [核心概念](concepts.md) —— 六类结论、证据形式、E0–E5 的适用范围。
7. [数据契约](data-contract.md) —— product-reasoning、study、evidence、judgments、商业节点与报告写入权。
8. [CLI 参考](cli.md) —— 命令、参数、产物和退出码。
9. [平台与连接器](connectors.md) —— 数据在哪、如何合规补证、哪些路线被阻断。
10. [研究闭环](research-loop.md) —— 缺口检测、信封授权、多轮复审与候选证据。
11. [决策复盘](cli.md#review决策复盘) —— 审计门、决策就绪、可证伪、偏差与交付物核验。
12. [SURE 引擎](sure-engine.md) —— 产品主链与研究支撑引擎的关系。
13. [故障排查](troubleshooting.md) —— 安装、断链、门禁、采集与 MCP。

## 一句话原则

> 先证明推导没有断，再看证据能支持到哪里；记录数不是用户数，主链完整不等于产品/商业成功，门禁通过不等于人工签收。
