# 五类产品：同一主链，不同验证体系

askovo 用同一入口覆盖软件、硬件、消费品、汽车、手机。五域都使用：

> **场景 → 用户 → 痛点 → 需求 → 特性 → 产品 → 商业**

领域包只改变研究方法、证据形式、配置基线、安全边界和验收参数，**不分叉主链 schema，也不把 Askovo 变成五套独立工具**。主链定义见[产品推理主链](product-reasoning.md)，岗位方法依据见[岗位方法论](product-methodology.md)。

## 总览

| 领域 | 主链发现重点 | 配置/上下文基线 | 独立专业门 | 典型禁推 |
|---|---|---|---|---|
| 软件 / SaaS | 工作流、任务、采用、留存、付费 | 产品/实验版本、平台、队列、时间窗 | 可用性、Beta、实验、发布与回滚 | 态度≠使用；活跃≠需求；观察≠因果 |
| 硬件 / IoT | 空间、安装、学习、维护、生命周期 | HW/FW/BOM、供应商、工艺、批次、环境 | 设计/过程验证、法规、供应、RMA | 台架≠用户价值；EVT/DVT/PVT≠需求；Beta≠认证 |
| 消费品 | 场合、包装、感官、习惯、复购 | 配方、包材、批次、SKU、渠道、购买周期 | 感官、稳定性、法规宣称、质量、复购 | 一次喜欢≠复购；CLT≠HUT；意愿≠销量 |
| 汽车 / ADAS | ODD、HMI、误用、分心、接管、真实使用 | 车辆 HW/SW、市场配置、协议、路线、暴露 | 功能安全、SOTIF、网络安全、法规、PPAP | 诊所/模拟器≠道路安全；零事件≠安全；用户试验≠认证 |
| 手机 / 可穿戴 | 握持、系统任务、影像/续航/信号、生态 | 设备、形态、OS/App、网络、权限、版本 | 移动质量、兼容、商店、灰度、vitals、RMA | 跑分≠体验；精选样张≠日常；E3≠可发布 |

## 1. 软件 / SaaS / App

### 七节点怎样落地

- **场景**：真实工作流、触发和任务上下文，不把“在线”当场景。
- **用户**：job executor、管理员、采购、IT/安全、维护者和受益者。
- **痛点**：手工绕行、重复录入、错误、等待、切换成本及结果损失。
- **需求**：可观察的工作结果与约束，而不是“加 AI”“加导出”。
- **特性**：候选工作流或能力，比较不同方案并测试危险假设。
- **产品**：完整任务价值、依赖、权限、数据、支持和回滚边界。
- **商业**：订阅/席位/用量/服务模式、净收入留存、CAC、毛利、实施与支持成本、渠道和扩张条件。

### 生命周期与验证

| 阶段 | 主要方法与有限结论 |
|---|---|
| discovery | 关键事件访谈、情境访查、日记、工单/日志三角验证 |
| concept | 概念测试、可点击原型、Concierge/Wizard-of-Oz、真实承诺 |
| prototype | 形成性任务测试、任务分析、无障碍 |
| validation | Beta、总结性基准、A/B、队列/漏斗 |
| pricing | VW/GG/联合分析与付费试点，声明意愿和交易分开 |
| prelaunch | Beta、无障碍、专家红队、发布与回滚评审 |
| postlaunch | 队列、遥测、实验、流失访谈与运营回流 |
| audit | 专家审阅、行为分析和主链/证据断点复核 |

**禁推**：SUS/UMUX-Lite/SEQ 不证明需求或付费；A/B 只回答已测指标的增量；功能采用不自动等于产品结果。

## 2. 硬件 / IoT / 消费电子

### 七节点怎样落地

- **场景**：物理空间、安装、维护、异常恢复和环境边界。
- **用户**：使用者、安装者、维护者、购买者和旁观者。
- **痛点**：返工、失败、维护成本、替代行为和实际后果。
- **需求**：带环境、接口、单位、阈值、容差和验证方式的系统目标；法规/危险/供应需求另有来源，不能全伪装成用户痛点。
- **特性**：looks-like/works-like/整合样机分别回答不同问题。
- **产品**：指定 HW/FW/BOM/工艺基线下的完整价值与生命周期交付。
- **商业**：BOM、模具/认证、渠道库存与账期、退货/RMA、保修、安装服务和单品毛利；样机支持不等于可量产商业。

### 验证与专业门

| 阶段 | 方法与边界 |
|---|---|
| discovery | 家庭/工作现场观察、日记、替代行为 |
| concept | 外观/CMF、握持/够取、概念与架构取舍 |
| prototype | 原理/工程样机任务、安装和异常恢复 |
| validation | 设计验证、现场试用、实验室与真实环境分别记录 |
| prelaunch | 生产过程验证、批次一致性、RMA 预案、法规/供应准备 |
| postlaunch | 遥测、RMA、维修、复购、变更影响与复测 |

EVT/DVT/PVT 是常见工程实践标签，不是统一需求证据或固定行业阈值。必须保存实际退出准则、配置和原始结果。市电、锂电、高温、运动件、激光/射频、化学品先做工程风险审查。

## 3. 消费品

### 七节点怎样落地

- **场景**：购买、准备、食用/使用、储存、分享和处置场合。
- **用户**：购买者、实际使用者、家庭成员、弃用者和渠道角色。
- **痛点**：预期落差、使用摩擦、替代习惯和后果。
- **需求**：消费者结果与约束；实验室、法规和宣称义务另列。
- **特性**：概念、配方、包装、规格等候选，明确刺激物与批次。
- **产品**：指定配方/包材/批次/SKU/渠道的完整交付。
- **商业**：价格×规格×渠道毛利、促销、铺货/缺货、首购与复购队列、退货和损耗；免费样品继续使用不是复购。

### 四条证据线不能混

1. **概念/包装**：理解、相关性、差异化、申报意向；不证明实物体验或销量。
2. **CLT/感官**：受控条件下的喜好、偏好或差异；训练评价员的分析型感官与普通消费者喜好也要分开。
3. **HUT**：真实准备、用量、共享、储存、摩擦和弃用；不外推付费复购。
4. **复购队列**：首购者在明确购买周期内再次付费；需要首购/复购事件、窗口、渠道、缺货、促销和分母。

放大、稳定性、包材相容、法规宣称、质量和供应各有独立放行。免费样品继续使用不等于复购，感官喜欢不等于功效或安全。

## 4. 汽车 / 智能座舱 / ADAS / 车载软件

### 七节点怎样落地

- **场景**：ODD、路线/天气/交通、主次任务和合理可预见误用。
- **用户**：驾驶员、乘客、车主、购买者及受影响交通参与者。
- **痛点**：任务错误、混乱、眼离路、workload、误用/近失及其后果；高信任不等于安全。
- **需求**：HMI 任务与车辆/ODD 目标；安全、网络安全和法规义务有独立祖先与验证链。
- **特性**：原型、模拟器、真车和后期配置分别提供不同证据。
- **产品**：指定车辆 HW/SW/市场配置，连接 HMI、性能、安全、法规、PPAP 和 OTA 边界。
- **商业**：车型配置/选装率、BOM 与供应商成本、认证和保修、渠道返利、SOP/OTA 投放及售后成本；用户偏好不等于车型商业成立。

### 验证环境不能互替

| 环境 | 能回答 | 不能替代 |
|---|---|---|
| 购前深访/配置 | JTBD、场景、配置/价格取舍 | 意向≠销量 |
| 静态诊所 | 造型、空间、上下车、配置理解 | 停车≠行车分心 |
| 动态诊所 | 驾乘坐、噪声、操控感知 | 受控路线≠全部交通 |
| 停车实车/台架 | HMI、可达、视野、学习、误用 | ≠真实驾驶负荷 |
| 模拟器 | 可重复 HMI 比较、分心、接管 | ≠真实事故率 |
| 封闭场地 | 真车操控、低速空间、受控 ADAS | 零事件≠开放道路安全 |
| 实际道路 | 后期低风险生态验证 | 不得故意制造危险 |
| 自然驾驶 | 日常使用、暴露、误用、近失 | 相关≠因果 |
| OTA/App | 灰度、日志、崩溃、留存 | 不能替代工程 V&V |

ISO 26262、ISO 21448/SOTIF、ISO/SAE 21434、法规/NCAP、APQP/PPAP 各由专业责任人和流程处理。Askovo 保存外部记录引用与覆盖状态，不宣称自动认证。道路研究继续执行 S0 人工安全门。

## 5. 手机 / 平板 / 可穿戴

### 七节点怎样落地

- **场景**：设备形态、OS/App、网络、权限、前后台/锁屏、真实任务和中断。
- **用户**：购买者、使用者、家庭成员、辅助技术用户、售后及不同设备/版本队列。
- **痛点**：状态丢失、断连、发热、续航、失败、迁移和支持成本。
- **需求**：真实任务结果、质量预算、隐私与支持矩阵。
- **特性**：原生能力、交互、影像/续航/信号方案及降级路径。
- **产品**：硬件、系统、App、云服务、商店与售后的完整价值交付。
- **商业**：BOM 与上市价格、运营商/零售渠道、服务与生态收入、保修/退货、版本支持成本和换机周期。

### 验证对象

| 对象 | 方法 |
|---|---|
| 购前卖点 | 深访/日记、MaxDiff/联合分析、配置取舍 |
| 握持/佩戴/系统 | 手型/姿势任务、新手/熟手、辅助技术 |
| 生命周期 | 切 App、锁屏、旋转/折叠、弱网、权限拒绝、进程恢复 |
| 相机 | 同场景实拍、失败率、盲评 |
| 续航/发热/充电 | 实验室曲线与真实一天日记 |
| 信号/定位 | 同路线/运营商/时段外场 |
| 系统更新 | 同机前后/分批 holdout、旧版与后端兼容 |
| 发布与上市后 | 设备×OS 矩阵、灰度/回滚、vitals、退换/维修、复购 |

跑分/规格不等于体验，精选样张/平均值掩盖偶发失败，Beta 无投诉不等于可发布。儿童、老年和残障用户需适当参与与保护；自动扫描不替代真实辅助技术任务。

## 6. 多类职责如何使用同一领域包

| 职责 | 共同输入 | 领域化交付 |
|---|---|---|
| 产品经理 | 全链、候选方案、范围、非目标、验收、商业门与残余风险 | 决策 memo、最终签收、跨职能 gate 输入 |
| 用户研究 | 主链缺口、样本、证据、反证、替代解释、语义复核 | 研究计划、需求判断、research-status、补证与复测 |
| 用户运营 | 场景×用户、痛点语言、异议、版本/队列、干预与指标口径 | ops、postlaunch tracker、反馈与变更回流 |
| 市场研究/分析 | 商业节点的市场边界、细分、替代、渠道、价格与规模口径 | MRD、市场研究证据和估计不确定性 |
| 需求研究/分析 | 用户/市场需求、约束、优先级、验收和追溯 | PRD、需求台账和变更影响 |
| 商业分析 | 产品、市场、支付、成本、资源和风险 | BRD、单位经济、商业门与停止条件 |

外部 PLM/QMS、实验平台、法规与认证记录用稳定引用连接，不由 Askovo 重造。任何 `pass` 都不替代专业签收、跨职能资源决策或风险接受。
