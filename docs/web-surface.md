# Web 阅读面

`askovo deliver <study> --kind web` 把同一份研究工件渲染成一页可以顺着读下去的自包含 HTML：`06-report/web/index.html`。

它回答的不是“结论是什么”，而是“一个业务读者从打开到看懂，需要经过哪几步”。所有文字、数字、图表、引语和证据都由同一条七节点主链（`04-findings/product-reasoning.json`）和同一份证据投影出来，不产生第二个事实源；它只是把 CLI 已经能写的 `plan.md` / `analysis.md` 排成可读顺序。

## 命令

```bash
askovo deliver ./study --kind web
```

输出：

- `06-report/web/index.html` —— 单文件页面，CSS 内联，图表是内联 SVG，不加载任何外部脚本、字体或图片；
- `06-report/web/assets/` —— 仅当证据记录带本地截图字段（`capture_screenshot_ref` 或类似本地路径）时生成，复制时加 `sha256[:12]-` 前缀，单文件上限 8 MB，超过则跳过并在结果的 `warnings` 里记录。

页面带 `noindex`，不面向搜索引擎公开。`--kind web` 与 `plan` / `decision` / `report` 一样只读主链，不改写 `study.json`、需求判断或证据库。

## 阅读顺序

页面顶部是页内目录，正文按业务读者的疑问排列：

1. **怎么读** —— 四类证据标签的图例：事实 / 自述 / 推导 / 我的判断。
2. **现在与判断形成时间** —— 「现在：数字与图表」与「判断形成于」两张卡片并列。
3. **结论与推进建议** —— 每条已决主链一句话结论、负责人、截止时间与证据强度。
4. **七节点推理** —— 场景 / 用户 / 痛点 / 需求 / 特性 / 产品 / 商业，每节给●◐○依据强度、数据基础与用户原话。
5. **证据墙** —— 每条记录一张卡：标签、原文摘录、来源与时间、被哪些环节引用、本地截图、原帖链接，分级代码只放卡片底部小字。
6. **数据分布** —— 来源构成、语料用途、证据标签分布三张条形图，加七节点覆盖图。
7. **可复用打法** —— 研究路径、判断怎么形成的、下次可以直接复用的动作。
8. **风险与下一步** —— 替代解释、反面信号、下一步验证。
9. **方法档案** —— E0–E5 分级、行为类型、资格标记、审计与增量状态。
10. **边界** —— 本页不证明什么。

## 四类标签与 E0–E5 的对应

正文只出现四个词，底层分级照旧：

| 阅读标签 | 含义 | 底层判定 |
| --- | --- | --- |
| **事实** | 已经发生的事：有人做过、接受过、付过钱，或一个可核实的规模数字 | `behavior_kind` 属于 `problem_behavior` / `solution_acceptance` / `commercial_transaction` / `attention_metric`；无 `behavior_kind` 时回退 E2 / E3 / E5 |
| **自述** | 别人说的：自述、意愿、抱怨 | `behavior_kind` 为 `statement` / `commercial_intent`；无 `behavior_kind` 时回退 E0 / E1 / E4+（价格或购买意愿）/ E4−（拒绝、退订等反向自述） |
| **推导** | 从事实和自述推出来的判断 | 七节点的结论与理由 |
| **我的判断** | 团队做的选择：做哪条链、先验证什么、什么算失败 | 已决主链、决策记录 |

两个容易误读的映射，页面在悬停提示里写明：

- E4+ 是**购买意愿或报价**，不是付费行为，标“自述”；
- E5 里的注意力指标只描述规模，标“事实”，但这只是“规模是事实”，不是“需求被证明”。

`behavior_kind` 优先于 E 等级：一条 E5 只要 `behavior_kind=attention`，就是规模事实而不是需求事实。同一套 `label_for` 也供 `plan.md` 的「证据类型：事实 N 条 · 自述 N 条」使用，两份交付标签一致。

## 时间分层

日更的数字和按周期写的判断本来就不在同一时间轴上。页面把两者拆开显示，而不是用一个“更新时间”糊在一起：

- **「现在：数字与图表」** 读最新数据文件的时间、证据条数与来源族数、证据时间跨度、增量版本（`askovo delta`）、结构审计状态；
- **「判断形成于」** 读判断链最后一次写入的时间、审计生成时间、人工复核状态，并给出重跑命令。

当证据文件比判断链新，页面顶部出现红色提示：**数字已更新，结论文字尚未重算** —— 说明数字、图表和证据墙是当前值，结论与七节点文字仍是上一版，并给出 `askovo deliver "<study>" --kind web` 的重跑命令。增量研究有未处理的来源变化（`needs_re_review` / `stale`）时另有一条提示，指向 `askovo delta`。

`plan.md` 里对应的一句话是：

> 时间分层：数字与图表截至最新输入时间，判断文字形成于判断链最后一次写入。两者不一致时以数字和图表的生成时间为准，并重跑 `askovo deliver <study> --kind plan` 重新生成判断。

数字陈旧不等于结论错误，只表示该重算。重跑后再人工看一遍标签与判断，`analyze` 不会自动改写证据等级或把结论升级为 `validated`。

## 边界

- 页面是只读投影：不改写主链、不写需求判断、不升级证据等级、不生成新结论；
- 四类标签是阅读辅助，**不是**证据分级本身；方法档案保留 E0–E5、`behavior_kind`、`measurement_integrity`、`claim_eligibility`；
- 页面自包含、不联网：没有外部脚本、字体和图片请求；证据里的原帖链接只是可点的来源，不在页面内抓取；
- 不证明总体发生率、市场规模、真实付费、因果、发布就绪或商业成功；渲染完成不等于人工签收。

## 验证

```bash
askovo deliver examples/sample-study --kind web
python3 -m unittest tests.test_web_surface
```

测试覆盖：页面写出且包含四类标签与时间分层文案、自包含（无外部资源、锚点只指向页内）、数字陈旧时给出提示与重跑命令、没有判断链时仍能渲染、MCP `askovo_deliver kind=web` 返回 `written`。
