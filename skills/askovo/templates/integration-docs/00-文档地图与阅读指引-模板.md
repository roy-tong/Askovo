## 1. 这套文档如何组织

主链固定为：

```text
scene → user → pain → need → feature → product → business
场景   → 用户   → 痛点   → 需求   → 特性    → 产品     → 商业
```

每条主链至少登记：

| 字段 | 本项目位置/内容 |
| --- | --- |
| chain ID / title | ____ |
| `context_key` | ____ |
| `demand_judgment_id` | ____ |
| chain 状态 | draft / hypothesis / decided / rejected |
| 反证、缺口、下一验证 | ____ |

`decided` 只表示在当前证据与约束下作出产品决策，不表示产品已被证明。需求判断的 `validated` 仅表示其证据门状态，不能改写成主链或产品“已验证”。

## 2. 文档体系与投影边界

| 文档 | 从主链读取 | 输出 | 不得独立修改 |
| --- | --- | --- | --- |
| `02-MRD` | scene / user / pain / need | 市场、用户、痛点与需求视图 | 不得创造新 persona 或把功能请求改名为需求 |
| `03-PRD` | feature / product，并回读前四节点 | 特性、形态、范围、非目标与验收 | 不得新增无 Need 来源的特性 |
| `01-BRD` | 全链 + 商业证据与资源约束 | 投入、收费、业务门和停止条件 | 不得把商业目标倒写成用户需求 |
| `04-缺口审计` | 七节点、六条推导边、各投影 | 缺口、矛盾、补法与修改触发器 | 不得只在整合文档里悄悄修正 |
| `05-定价研究` | 主链 + 交易/成本/替代证据 | 收费方式与定价门 | 不得用价格假设证明需求 |
| `06-关键五问` | 高影响节点与边 | 最可能改变决策的问题 | 不得用叙事覆盖未知 |

### 下游表达与运营视图

卖点、话术、场景分群、异议处理和运营干预都从同一条主链派生：

```text
scene/user/pain/need + feature/product
→ 价值主张与卖点
→ 用户运营分群、表达、干预和回流
```

卖点不是需求的上游，运营反馈必须经证据记录和人审后回写主链，不能直接改写成产品事实。

## 4. 按角色的阅读路径

- **产品经理**：本文 → 七节点主链 → MRD/PRD/BRD 的取舍与业务门 → 04 高优先级缺口。读完应能回答“为谁、解决什么、做什么、凭什么赚钱、何时停止”。
- **市场研究/分析**：MRD 的市场边界、细分、竞品、渠道、价格、规模口径与不确定性 → 04 市场缺口和下一研究。
- **需求研究/分析**：PRD 的需求来源、优先级、验收、追溯和变更 → 04 断链与孤儿项。
- **商业分析**：BRD 的收入、成本、单位经济、资源门、风险与停止条件 → 04 商业缺口和复审点。
- **用户研究**：本文的主链地图 → 04 节点与边缺口 → 证据记录/需求判断 → 访谈或其他验证工具包 → 回写主链。读完应能回答“哪一步最弱、什么证据能改变决策”。
- **用户运营**：MRD 场景与用户分群 → 痛点和替代语言 → 下游价值主张/异议 → 运营跟踪与反馈回流。读完应能回答“对谁说、在何场景说、用什么证据约束表达”。
- **研发/设计**：PRD 特性与产品 → need→feature→product 推导 → 验收与非目标 → 04 阻塞项。

## 5. 证据标签与强度纪律

可按项目以下来源建立标签，但标签不能替代 record ID、时间窗和适用范围：

| 标签 | 含义 | 使用纪律 |
| --- | --- | --- |
| 【官方】 | 官方机构或公司公开材料 | 多为语境或供给事实，不自动成为目标用户需求证据 |
| 【R】 | 本项目社区/论坛语料 | 记录量不是用户数，热度不是需求强度 |
| 【A】 | 电商评论或交易相关材料 | 区分评论、购买意图、实际交易和持续使用 |
| 【F】 | 竞品/行业公开信息 | 主要是替代与价格语境，不自动证明本方案被接受 |
| 【I】 | 访谈一手记录 | 按单条内容确定 E 等级；多人一致只影响覆盖与置信度 |
| 【假设】 | 尚无直接证据的团队假设 | 不得包装成事实 |
| 【U-判断】 | 团队或决策者判断 | 代表决策意图，不冒充用户证据 |

E0–E5 按单条记录直接观察到的最强证据定级，**多人一致不得把低等级材料升级为高等级材料**。可用性、性能和安全证据也不硬塞进需求/商业 E 等级。
