## 1. 这次整合做了什么

> 填写指引：两到四句。研究层有多少篇文档/多少语料、为什么需要一个浓缩层、整合成"几份正式 + 几份模块"。

示例（合成）：研究层四个目录产出了约 60 篇研究文档，但没有一个面向决策的浓缩层。本目录把研究结论整合为**三份正式文档（BRD/MRD/PRD）+ 三份模块文档（缺口审计/定价/关键五问）**，并与研究层建立引用链——任何文档中的判断都能回溯到研究层出处。

**整合原则**（三条，照抄并遵守）：

1. **不新增结论**——整合文档里的每条判断都能回溯到研究层材料；新增的内容只有三类：①结构化重组 ②跨文档矛盾的显式暴露 ③原文没有的缺口标注。
2. **不掩盖矛盾**——研究文档之间对不上的数字、推理跳跃、证据强度被高估的地方，全部在 `04-缺口审计` 里列出并编号，不在整合文档里悄悄抹平。
3. **标注证据强度**——每条结论带证据标签（§5）和强度评级（强/中/弱/空白）。

## 3. 三份文档的分工（防重复劳动）

> 填写指引：下表照抄结构，按项目微调措辞；数据流图必须保留"不要跳步"箭头。

**一条数据流（不要跳步）**：

```
用户经历（语料金标 + 访谈）
  → MRD：谁在什么情境遇到什么问题（persona × 三时刻）
    → PRD：产品用什么特性回应（特性 ← MRD 卖点/用户方案反推）
      → BRD：这门生意怎么成立（阶段门 ← PRD 验收 ← MRD 判断）
```

| | BRD | MRD | PRD |
| --- | --- | --- | --- |
| 回答的问题 | 该不该做、怎么赚钱、什么算成功 | 为谁做、为什么是要、卖什么 | 做什么、长什么样 |
| 核心交付物 | 阶段门 + 待决策事项 | 三时刻卖点 + 需求清单 | 关键特性 + 产品形态 |
| 不回答 | 功能怎么做 | 功能怎么做 | 市场值不值得做 |
| 谁看 | 决策层 | 产品/市场 | 产品/研发/设计 |

- **MRD 管"为什么值得做"**：人群、情境、竞争、市场结构。三时刻卖点放 MRD——它们是市场判断，不是功能清单。
- **PRD 管"做什么"**：特性、形态、优先级、不做什么。所有特性必须能回指 MRD 的一个情境或卖点。
- **BRD 管"怎么活"**：北极星、单位经济框架、阶段门。BRD 的每个阶段门引用 PRD 的验收指标。

## 4. 按角色的阅读路径

> 填写指引：给 3-4 类角色各写一条 5-7 跳的路径，标注总时长；"读完后你应该能回答"一句可留。

示例（合成）：

- **决策者（约 30 分钟）**：本文档 → `06-关键五问` → `01-BRD` §0-1（业务公式与阶段门）→ `04-缺口审计`。追问任何数字时回研究层出处。
- **产品/市场负责人（约 90 分钟）**：`02-MRD` 全文 → `03-PRD` §0-1 → `05-定价研究`。
- **研发/设计（约 60 分钟）**：`03-PRD` 全文（尤其约束与验收）→ `04-缺口审计` 的结构性缺口。
