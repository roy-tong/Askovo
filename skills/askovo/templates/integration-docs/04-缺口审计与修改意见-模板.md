# 04 · 缺口审计与修改意见

> 对三份核心文档（+模块文档）逐章列出：判断缺什么证据、谁补、什么结果触发修改。用途：先于尽调发现漏洞；一手数据回流后的更新路线图。
> 填写指引：本模板是**回链机制的反向一半**——整合层的每条关键判断在这里接受"缺口审问"，并与研究层假设（study.json hypotheses 或研究层假设清单 H 编号）双向对齐。"补法"列的一手研究类动作统一指向 `../interview-kit/`（A-6 访谈研究包）。

# 0. 摘要：最严重的 __ 个问题

> 填写指引：编号 S1-Sn，按"不修补会导致决策错误"排序；每条一句话 + 所在文档章节。若有被用户纠正后撤销的审计结论，单列"被撤销的审计结论"并保留撤回记录（防错误扩散）。

# 1. 审计范围与方法（可选）

> 填写指引：审计了什么（文档×研究层出处抽查）、审计边界（只看材料不看人/团队能力）、先说做得好的部分（避免审计一边倒）。

# 2-4. 逐文档缺口表（BRD / MRD / PRD 各一张）

> 填写指引：一行 = 一条判断。"判断"列复制整合层原文（带章节号），"缺口"列写证据状态（零数据点/仅个案/单一来源/时间窗不符），"触发修改"列必须可观察。

# 5. 横切缺口（多文档共同依赖）

> 填写指引：三文档共同的前置空白，通常 2-4 条。常见项：付费意愿零数据点（三文档共同的 S1 前置）；角色身份未验证（词表不推职业）；某语言/区域侧全缺。最后一条固定保留：

- **研究层↔整合层同步规则**：研究层新增数据 → 先更新研究层对应文档 → 再触发整合层对应章（防两层数字漂移），并在本文件 §8 登记触发事件。

# 6. 数字与口径不一致清单

> 填写指引：项目内部数字冲突逐条编号列出（文档 A §x 说 N1，文档 B §y 说 N2，原因，以哪个为准）；与本项目结论冲突的外部数据单列。整合文档只标注不替团队修正——判断需决策者拍板。

# 7. 逻辑严谨性审计（常见病清单）

> 填写指引：逐条自查，命中即编号登记：证据分级被压扁（不同可靠性来源共用标签）；不可证伪的辩护（任何结果都能解释成支持）；幸存者偏差（只看成功竞品，不看墓地/流失）；把判断当事实（团队战略输入写成市场证据）；过度解读小样本；竞品分析三遗漏（真对手"不消费/现有方案"、墓地、时间窗不匹配）；时间窗错配（用历史快照推当下）。

# 8. 外部事实核验清单（本会话未能完成时）

> 填写指引：未核验的关键论据按 P0/P1/P2 列出：论据、被谁引用、核验方法、状态。写明"未核验"与引用时的强制提示。

# 9. 修改意见

> 填写指引：P0 必须改（不改会导致决策错误）/ P1 建议改 / P2 可选。每条指明改哪个文档哪一章。

# 10. 补数据清单与优先级

> 填写指引：把所有"补法"列去重汇总，按 成本×信息量 排序；一手研究项统一注明"执行包见 interview-kit"。
