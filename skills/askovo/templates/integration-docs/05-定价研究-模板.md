# 05 · 定价与收费研究

> v__（____态：框架态 / 定价态）。
> 填写指引：先判定状态。**框架态纪律：无 BOM/供应商报价/试产数据时，本文不给出任何建议售价**——只交付收费方式比较、价格带锚点地图与"何时才允许定价"的门槛；定价态：交付定价公式与 SKU 结构。字段来源速查：替代成本 ← MRD 需求清单"用户现在的办法×现在花的钱" + 研究层 E2 替代方案证据；价格锚点 ← 研究层竞品价格调研与付费证据文档（E4+ 记录）；支付意愿 ← E4+/E5 记录、概念测试、conjiont 类研究（interview-kit / 研究层一手研究执行包）。

# 0. 结论

> 填写指引：3 条以内。通常包含：①收费方式的优先级高于价格数字；②默认收费假设及其依据；③价格数字的解锁条件（框架态）或定价公式（定价态）。

示例（合成，框架态）：
1. **收费方式的优先级高于价格数字**：三种方式的验证顺序 = BRD 收入层顺序。
2. "____"是____线的默认假设【来源】。
3. 价格数字的解锁条件：BOM 报价 + 试点期真实付费意愿数据，二者缺一不出价。

# 3. 需求价值核算（替代成本法）

> 填写指引：定价态的主方法。从 MRD 需求清单带过来与付费相关的需求，逐条列"用户现在的办法/现在花的钱/痛点"，然后把产品定位为"这几笔支出的合并"，写出定价公式（例：替代价值合计 → 定价取其一半上下 → 用户一年出头回本）。每一项必须有市场成交记录（锚点），反例（纯功能无数据支撑卖不上价的失败众筹/产品）也要列。框架态的等价物是"决定我们能站在哪个价格带哪一侧的增益实验"，写清实验与价格带的关系。

# 4. 竞品价位 × 交付矩阵

> 填写指引：竞品一行，"它交付什么/没交付什么"各列打勾；`?` 表示公开信息未确认，引用时注明。矩阵用来回答"我们在哪个空格、凭什么贵/便宜"。

# 5. 何时才允许定价（门槛清单）

> 填写指引：checkbox 清单，全勾才出 v2 定价文档（含 SKU 与价格公式）。常见四项：

- [ ] BOM/供应商有效报价（PRD 形态确认后）
- [ ] 差异化增益实验结果明确
- [ ] 试点期真实付费意愿（概念测试 + 机构报价反应）
- [ ] 单次服务/单台成本实测（准备/交付/折旧，写明口径）

# 6. 风险与反证

> 填写指引：收费方式被试点推翻时"矩阵重排，不硬推订阅"；效果感知问题先查感知再谈降价；**一切收费测试必须在真实负担披露（重量/时长/图示）后进行——隐瞒负担测到的价格无效**。
