# 02 · MRD 市场需求文档

> 项目 · 主链版本 · 投影版本。本文是 **市场研究与市场分析** 的正式产出，投影 `product-reasoning.json` 中 `scene / user / pain / need` 以及 `business` 的市场部分；不是第二事实源。
> 填写纪律：每个关键判断引用 `chain.node` 或 `chain.上一节点→下一节点`；市场数字引用证据和方法。需要改语义时先回主链修改，再同步本文。

## 0. 摘要：市场侧最重要的六个判断

每条包含 chain/node 引用、证据状态和决策含义。至少回答：

1. 哪个场景最值得进入，为什么；
2. 该场景中哪些用户角色已覆盖、哪些只是假设；
3. 当前替代方案在哪里失效，造成什么后果；
4. 用户需要达成什么结果，约束和度量是什么；
5. 哪个反证或满意替代方案最可能推翻当前方向；
6. 哪个节点或推导边最弱，下一步如何补证。

不得把记录数写成用户数，把功能请求写成需求，或把商业目标倒写成用户痛点。

需求使用解法中立的用户语言，描述要达成的结果及约束。不要写“需要增加____按钮/模型/设备”，这类内容属于候选特性或功能请求。

### 5.2 痛点为什么构成需求

逐条写 `PR01.pain→need` 的 rationale：

- 为什么该痛点值得改变，而非可忽略的不便；
- 期望结果是否直接回应摩擦与后果；
- 是否存在更低成本、非产品化或不改变的方案；
- 哪些证据只支持 `hypothesis/needs-validation`，不能声称需求判断 `validated`。
