# 01 · BRD 商业需求文档

> 项目 · 主链版本 · 投影版本。本文是 **商业分析** 的正式产出，投影 `04-findings/product-reasoning.json` 的 `business` 节点；市场研究/分析产出 MRD，需求研究/分析产出 PRD，本文不另建用户、需求、特性或产品事实。
> 假设态纪律：收入、成本、市场规模均未验证时，所有数字只能是带口径的外部锚点或显式假设；用商业验证和业务门替代收入幻想，不用商业目标倒写用户需求。

## 0. 一页商业决策

### 0.1 当前主链与决策对象

| 字段 | 内容 |
| --- | --- |
| chain / context_key | ____ |
| scene / user / pain / need | 各用一句话摘要并引用 `PR__.node` |
| feature / product | 各用一句话摘要并引用 `PR__.node` |
| chain 状态 | draft / hypothesis / decided / rejected |
| 本文商业决策 | 投入 / 试点 / 收费测试 / 扩张 / 收缩 / 停止 |
| 决策人、日期、复审触发器 | ____ |

chain `decided` 只表示产品决策已作出，不表示产品或商业已被证明。需求判断 `validated` 只表示其证据门状态，不等于商业成立。

### 0.2 业务公式

把生意拆成相互依赖的因子，任一因子为零都可能使业务不成立；每个因子指向主链或商业证据：

```text
可持续业务 =（PR__.product 能提供可信结果）
           ×（相对 PR__.pain 中的替代方案有净增益）
           ×（能嵌入 PR__.scene/user 的真实工作流）
           ×（目标付费者按____付费/续约）
           ×（交付成本与风险处于____边界）
```

| 因子 | chain/node/edge 或商业证据 | 当前状态 | 最便宜验证 |
| --- | --- | --- | --- |
| 结果可信 | ____ | ____ | ____ |
| 相对替代有增益 | ____ | ____ | ____ |
| 工作流采纳 | ____ | ____ | ____ |
| 付费与续约 | ____ | ____ | ____ |

## 2. 收费与单位经济

### 2.1 收入结构假设

| 层级 | 收费形态 | 付费对象 | 对应 scene/user/product | 证据状态 |
| --- | --- | --- | --- | --- |
| L1 ____ | ____ | ____ | ____ | 外部锚点 / 假设 / 本项目行为证据 |
| L2 ____ | ____ | ____ | ____ | ____ |

写清各层是否相互补贴、是否存在“学会即毕业”等非续费目标，不得预设订阅、复购或扩张。

### 2.2 单位经济

假设态没有供应商报价、BOM、试产或交付数据时，只列输入与解锁条件，不给整机成本、毛利或建议售价。成熟态列出单次服务工时、准备时长、折旧、人员成本、交付量、售后、渠道和退款口径。

详细收费方式与价格门见 `05-定价研究`。价格锚点、购买意图和真实交易必须分开，不用竞品报价证明本产品需求。

## 3. 产品与市场摘要

### 3.1 产品摘要

从主链和 PRD 投影，不重新创作：

- `PR__.feature.capability`：____；
- `PR__.product.form/scope`：____；
- `PR__.product.non_goals/acceptance_criteria`：____；
- `need→feature→product` 的关键假设：____。

### 3.2 市场与运营摘要

从主链和 MRD 投影：

- 首发 scene/user 及进入理由：____；
- pain/current_substitute 与替换障碍：____；
- 下游价值主张及禁止承诺：____；
- 用户运营的分群、干预与证据回流入口：____。

卖点是下游表达，不能替代主链推导，也不能省略真实负担和限制。

## 4. 为什么是现在与战略前提（可选）

分别列供给侧、需求侧和缺口侧证据。技术成熟、讨论热度、竞品融资或相邻市场付费都不能单独证明本主链成立。若业务建立在 IP、渠道、监管或技术增量等战略前提上，写明该前提影响哪个 chain/node/edge、什么结果会推翻它。

## 5. 预算与资源（成熟态或已有报价时）

按口径列人力、BOM、交付、售后、运营、合规和总预算；每项标来源与日期。缺少输入时写“待____数据回流后建立”，不得填假数。

## 6. 执行路径与业务门

| 门 | 主链/商业前提 | 可观察通过条件 | 不通过时修改什么 | 复审证据 |
| --- | --- | --- | --- | --- |
| G0→G1 | `PR__.need→feature→product` | ____ | 收缩场景、改需求/特性/产品或停止 | ____ |
| G1→G2 | 真实工作流与交付 | ____ | 改形态、流程或目标用户 | ____ |
| G2→扩张 | 付费、留存与单位经济 | ____ | 调整收费、成本或停止扩张 | ____ |

“不过怎么办”必须是可执行预案，不写“再努力”。产品决策变更先回写主链，再同步所有投影。

安全、伦理、隐私、监管和数据权利底线单列 HOLD/S0 熔断，触发即停，不以商业门通过抵消。

## 附录 A · 证据与推断边界

汇总证据 ID、来源、时间窗、分母、反证和缺口。记录数不是用户数；便利样本不能推总体；口头意愿不是交易；相关性不是因果；门禁通过不证明真实性或商业成功。
