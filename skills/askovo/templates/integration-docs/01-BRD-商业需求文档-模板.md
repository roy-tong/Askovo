# 0. 一页业务逻辑

## 0.1 业务公式（乘数结构）

> 填写指引：把生意拆成 3-5 个相乘的因子，任何一个为零则业务不成立。假设态必须声明所有乘数的验证状态。

```
一门可持续的业务 = （一次可信的 ____ 服务）
                 × （比现有 ____ 更好，或同样结果更省事）   ← 验证方式：____
                 × （能嵌入 ____ 的既有工作流）             ← 验证方式：____
                 × （____ 按 ____ 续约 / 付费）             ← 验证方式：____
```

示例（合成）：四个乘数全部未验证时，本文的主要作用是定义"每个乘数怎么被验证"，而非预测收入。

## 0.2 三个齿轮（验证顺序不可倒置）

> 填写指引：证据齿轮 → 工作流齿轮 → 收费齿轮。每个齿轮写清"产出物是什么"。顺序依据引用研究层的失败案例文档（墓地/死亡名单）。

1. **证据齿轮**（先转）：____（差异化的可引用效果声明）。
2. **工作流齿轮**：____（真实工作流的采纳记录：操作时长实测 + 留存行为）。
3. **收费齿轮**（最后转）：____（真实付费与续约）。
