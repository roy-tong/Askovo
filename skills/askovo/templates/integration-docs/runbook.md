# 整合层 runbook：研究层如何生长为 BRD/MRD/PRD 文档体系（B-5）

> 模板组 B-5 的入口文件。本组把研究层产物（askovo 研究目录或项目研究层目录里的报告、发现、判断）整合为一套面向决策的商业文档：文档地图、BRD、MRD、PRD、缺口审计、定价研究、关键五问。模板提炼自两个已完成项目的整合层（结构互相参照建立），模板中的示例均为合成内容，不含真实客户与公司名。

## 1. 什么时候用这一组

- 研究层已经产出结论层材料（`04-findings/insights.md`、`06-report/report.md`，或项目研究层目录下的专题报告），但**没有一份面向决策者的浓缩层**；
- 决策者需要的不是"研究状态报告"，而是"该不该做、为谁做、做什么、怎么收钱"的商业文档；
- 材料散落在多篇研究文档中，数字与判断需要统一口径并暴露矛盾。

不适用：研究层还没有可引用的结论（先回 askovo 主流程跑完 signals/report）；只要一份研究状态汇报（`askovo.py report` 已覆盖，不要用整合层替代它）。

## 2. 模板组清单

| 模板 | 回答什么 | 主要读者 |
| --- | --- | --- |
| `00-文档地图与阅读指引-模板.md` | 文档在哪、怎么读、证据标签是什么 | 所有人，第一入口 |
| `01-BRD-商业需求文档-模板.md` | 这门生意该不该做、怎么成立、什么算成功 | 决策者 |
| `02-MRD-市场需求文档-模板.md` | 为谁做、他们为什么要、凭什么被选 | 产品/市场 |
| `03-PRD-产品需求文档-模板.md` | 做什么、不做什么、验收是什么 | 产品/研发/设计 |
| `04-缺口审计与修改意见-模板.md` | 每条判断缺什么证据、什么结果触发改文档 | 所有人（先于尽调） |
| `05-定价研究-模板.md` | 怎么收费、价格带在哪、何时才允许出价 | 决策者/商业化 |
| `06-关键五问-模板.md` | 决定项目生死的问题与当前答案 | 决策者 |

## 3. 目录关系与引用规则

整合层是一个**新目录**（惯例命名 `0X-整合文档/`，编号接在研究层之后），研究层目录保持只读。

```text
项目/
├── 01..0N-研究层目录/        ← 只读输入（askovo 研究目录或专题研究目录）
│   ├── 01-sources/ 02-data/ … 06-report/   ← askovo 标准研究目录时
│   └── （专题报告 .md 若干）
├── 0X-整合文档/              ← 本组模板复制到此处后填写
└── 00-外部输入/原始材料/     ← 整合层不直接引用，一律经由研究层
```

引用规则（回链机制的正向一半）：

1. 整合层每条关键判断必须带来源标注，格式：`研究层目录/文档名 §章节`（项目结构）或 `研究目录路径 + record_id`（askovo 结构）；
2. 数字必须带证据标签（标签体系见 00 模板 §5），没有标签的数字不允许出现；
3. 整合层引用研究层结论时**不重复论证**——论证留在研究层，整合层只给结论+出处+缺口；
4. 原始层（语料、快照、逐字稿）不直接引用，一律经由研究层的中介文档。

## 4. 生长顺序（写作用的顺序，不是编号顺序）

编号沿用行业惯例（01-BRD 在前），但**生长顺序**是"谁吃研究层最多谁先写"。两个实例项目的共识数据流：

```
研究层（用户经历·语料·判断）
  → 00 文档地图（先画地图：研究层产物 → 引用点映射）
  → MRD（谁在什么情境遇到什么问题；三时刻卖点）
  → PRD（特性从 MRD 卖点反推；不做什么）
  → BRD（业务公式、阶段门 ← PRD 验收 ← MRD 判断）
  → 04 缺口审计（逐章暴露缺口与矛盾）
  → 05 定价研究 / 06 关键五问（按缺口与阶段门收口）
```

| 步骤 | 输入 | 动作 | 输出 |
| --- | --- | --- | --- |
| 1. 画地图 | 研究层目录全清单 | 逐目录登记"内容 + 整合层引用点"，定证据标签体系 | `00-文档地图` 草稿 |
| 2. MRD | 00 地图 + 研究层画像/场景/竞争/付费文档 | 浓缩为 persona、三时刻卖点、需求清单、口径纪律表 | `02-MRD` |
| 3. PRD | MRD 卖点与需求清单 + 研究层方案反应证据 | 卖点反推特性、定形态与 MVP 边界、写验收指标 | `03-PRD` |
| 4. BRD | MRD 判断 + PRD 验收 + 研究层付费/反证文档 | 业务公式、北极星、收入结构、阶段门、风险 | `01-BRD` |
| 5. 缺口审计 | 三份核心文档 + 研究层出处 | 逐章列 判断/缺口/补法/触发修改；列矛盾与口径冲突 | `04-缺口审计` |
| 6. 定价与五问 | BRD 阶段门 + 04 缺口 | 收费方式矩阵、价格锚点、何时允许出价；生死五问 | `05`、`06` |

例外：若项目已有明确战略原点（如 IP 溢价、既有渠道），BRD 的战略原点章先于 MRD 写——MRD 的用户研究重点取决于战略原点是否成立（实例项目一的处理方式）。

## 5. 状态裁剪：假设态 vs 定价态

两个实例代表两种成熟度，套模板前先判定项目处于哪态：

| | 假设态（证据验证前） | 成熟态（产品与定价已定） |
| --- | --- | --- |
| BRD 单位经济 | 只给框架不填数；以"验证乘数 + 阶段门"替代收入预测 | 完整单位经济、BOM、预算 |
| MRD 市场 | 相邻市场锚点 + 口径纪律；分母诚实写 0 | 自有市场数据 + 分层 |
| PRD | "MVP 边界与验收"，特性全部标注假设 | 完整 FR 清单、数据模型、SKU |
| 定价研究 | 收费方式比较 + 锚点地图；无 BOM 不给价（门槛清单） | 替代成本推导出定价公式与 SKU 结构 |

判定规则：BRD 模板里"单位经济"一节若任何输入是空的（无 BOM/报价/试点数据），整个文档组按假设态写，并把"何时才允许定价"清单写进 05。**强行填数违反两个实例共同的纪律。**

## 6. 质量检查（交稿前逐条过）

1. **整合三原则**（写进 00 模板 §1）：不新增结论（每条判断可回溯研究层）；不掩盖矛盾（对不上的数字、推理跳跃显式列出并编号，不悄悄抹平）；标注证据强度（每条结论带标签与强度评级）。
2. **回链抽查**：从三份核心文档随机抽 10 条关键判断，逐条回到研究层出处验证表述没有升级（研究层说"个案"，整合层不得写成"普遍"）。抽查结果记入 04 模板的修改日志。
3. **三文档分工不重复**：MRD 不写功能清单；PRD 不重论市场值不值得做；BRD 只摘要产品与市场。卖点放 MRD（是市场结论），特性放 PRD（是供给回应）。
4. **交付物硬性**：BRD 没有阶段门=没写完；MRD 没有三时刻卖点=没写完；PRD 没有从卖点反推的特性=没写完。
5. **口径纪律**：MRD 的"禁止/替代"表覆盖所有对外数字；便利样本数字一律带样本口径，不得外推总体（与 askovo 禁止推断一致）。
6. **证据分级不被压扁**：不同可靠性来源不得共用一个标签（实例项目一曾把"老板判断/外部材料/用户批注"混用一个标签后拆成三类）；文献锚点只作语境，不作用户需求证据。
7. **常见逻辑病自查**（来自实例项目一的审计教训）：不可证伪的辩护、幸存者偏差（只看成功竞品不看墓地）、把判断当事实、过度解读小样本、时间窗不匹配、竞品分析遗漏"不增加设备/不消费"的真正对手。

## 7. 版本与同步规则

- **整合层不产生新证据**。研究层新增数据（访谈/实验/试点）后：先更新研究层对应文档 → 再触发整合层对应章节 → 并在 `04-缺口审计` 的修改日志登记触发事件。
- 一手数据回流的通道见姊妹模板组 `../interview-kit/runbook.md`（A-6 访谈研究包）——04 缺口审计的"补法"列应指向那里。
- 与研究层撤回清单冲突的旧表述，以研究层为准，并在 04 修改日志记录。
