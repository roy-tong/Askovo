## 2. 开场白设计（三段式）

> 填写指引：开场从最近一次真实经历开始，不问态度不问同意度；录音授权在前。给出逐字话术。

示例（合成，全部替换为项目内容）：

1. **授权与边界**（30 秒）："今天聊天用于我们内部的____研究，全程录音只为整理准确，对外报告只用化名，随时可以停下或跳过任何问题。"
2. **经历开场**（不用"您觉得/您是否"）："先不讲我们的想法。能讲讲**上一次**你遇到 [核心场景] 是什么时候吗？当时具体发生了什么？"
3. **角色澄清**："这次的事里，你自己负责哪部分？谁说了算？"

禁止句式清单：您同意……吗 / 如果有一个产品……您会用吗 / 您愿意付多少钱（付费意愿只在经历与代价还原之后，经真实负担披露再问）。

## 3. 追问树（每个核心问题一株）

> 填写指引：主干=核心经历问题；分枝按"时机→现有办法→代价→失败时刻→花钱处→决定权"展开；叶子=可量化追问。追问的目的是还原 E1/E2/E3/E4 证据，不是收集态度。

```text
Q（核心经历）"上一次____是什么时候？"
├─ 时机与频率："多久遇到一次？最近一次和最糟的一次？"
│   └─ "那次后来怎么样了？"—→ 决定对不对（H3 校准点）
├─ 现有办法："当时你怎么解决的？"
│   ├─ "具体第一步做什么？"（E2：替代方案）
│   └─ "这套办法什么时候失灵过？"
├─ 代价："那次花了多少时间/钱/返工？"（E2：摩擦与后果）
│   └─ "为此花过什么钱？多久一次？"（E4- 锚点）
├─ 相关角色："这事谁签字/谁反对？"（机构线专用）
└─ 新信息钩子（收尾才用）："如果当时多一个____，你会拿它替换哪一步？谁会反对？"（E3，概念反应）
```

## 4. 概念/方案反应测试纪律（如有概念展示）

> 填写指引：概念描述必须真实负担披露（重量/时长/图示）；禁用未验证效果声明；只变一个变量（同人群内比文案、同文案比渠道，分开测）；记录漏斗各步，预购点击≠订单。

## 5. 执行时序与判定

> 填写指引：周次安排 + 里程碑判据（"若 H__ 与 H__ 同时被证伪 → ____"）；每场访谈后的消化时限（建议 48 小时内完成纪要与核验表更新，流程见 `runbook.md` §2）。

## 6. 深聊手册形态（提纲的最终形态，可选升级）

> 填写指引：当访谈对象是极少数关键人（创始人/决策者）且需要多轮迭代时，提纲升级为"深聊手册"：①一页结论放最前；②按主题分部（每部：立场一句话 + 论据 + 建议的表达话术）；③每版显式记录版本号与迭代原因；④"建议的表达"给逐字话术而不是要点。迭代纪律：换版不推翻已验证结论，只补新议题与修正被证伪的表述。
